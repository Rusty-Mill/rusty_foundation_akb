# Attachments, links, and content safety

**RM-COMMS-CONTENT-0001:** Every attachment/inline asset/link has stable identity, source generation, declared/detected media type, size/digest, classification, origin, authorization, retention, and inspection/transformation evidence.

**RM-COMMS-CONTENT-0002:** Attachments and remote content pass bounded content identification, malware/reputation inspection, quarantine, safe preview/transformation, DLP, and channel/provider policy before publication.

**RM-COMMS-CONTENT-0003:** Links bind intended destination/purpose, displayed text, tenant/campaign/message/recipient scope only where necessary, HTTPS and domain policy, expiry/revocation, redirect chain, anti-open-redirect controls, and privacy-safe tracking.

**RM-COMMS-CONTENT-0004:** Signed-action, download, login, unsubscribe, and preference links use distinct purpose-bound tokens with audience, expiry, nonce/replay, authority, minimal disclosure, revocation, and confirmation policy.

**RM-COMMS-CONTENT-0005:** Remote images/fonts/scripts/forms, active content, tracking pixels, CSS, SVG, and embedded resources follow restrictive channel profiles; unavailable remote content preserves meaning and accessibility.

**RM-COMMS-CONTENT-0006:** URL shorteners, provider rewriting, click scanners, safe-link gateways, and redirects are reported transformations and cannot silently alter domain trust or treat automated traversal as human engagement.
