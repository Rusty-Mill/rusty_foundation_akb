# Purposes, processing plans, and policy evidence

**RM-PRIVACY-PURPOSE-0001:** Purpose has stable issuer/namespace/revision, localized human description, operational definition, product feature/process, eligible subjects/data/actions, recipients, locations, retention, compatible secondary purposes, prohibited uses, and lifecycle.

**RM-PRIVACY-PURPOSE-0002:** A processing plan binds exact purpose generation, data categories/elements and necessity rationale, collection source, data actions, actors/roles, automated decisions, recipients/processors, region/transfer route, retention/deletion, protection, consent/preference or other policy evidence, and review authority.

**RM-PRIVACY-PURPOSE-0003:** Data actions distinguish observe/access, collect/receive, validate, store, organize, combine/link, infer/derive, analyze/train, personalize, decide, disclose/share/sell-like policy category, transfer, publish, restrict, archive, and dispose.

**RM-PRIVACY-PURPOSE-0004:** Processing is authorized only by a product-selected, counsel-reviewed policy decision over current context. Rusty Mill records the selected basis/evidence identifier and nonclaims without naming it universally lawful.

**RM-PRIVACY-PURPOSE-0005:** Material changes to purpose, subject population, data, actions, recipients, geography, retention, automation, or risk create a new plan generation and compatibility/re-notice/re-choice review; labels cannot silently broaden plans.

**RM-PRIVACY-PURPOSE-0006:** Purpose compatibility is an explicit policy result with original/new plans, relationship, context/expectations, data nature, consequences, safeguards, jurisdiction, reviewer, and time—not string or taxonomy similarity.

**RM-PRIVACY-PURPOSE-0007:** Runtime enforcement passes attenuated data views and operation capabilities matching the plan; ambient database/network/logging access cannot be justified by a purpose annotation alone.
