# Secret identity, versions, and metadata

**RM-SECRETS-VERSION-0001:** Names are product labels; provider identifiers and paths are provider-scoped; immutable `SecretGenerationRef` values identify exact versions without embedding secret data.

**RM-SECRETS-VERSION-0002:** Secret classes distinguish shared passwords, API keys, database credentials, cloud credentials, certificates/private keys, symmetric keys, bootstrap tokens, recovery material, signing/encryption handles, and provider-native opaque references.

**RM-SECRETS-VERSION-0003:** Create/replace uses expected version or conditional semantics, validates provider capabilities before accepting plaintext, and reports whether history, replication, backup, recovery, or rollback retains prior values.

**RM-SECRETS-VERSION-0004:** Metadata access has separate authority and disclosure policy; names, paths, targets, usernames, lease IDs, expiry, owners, rotation status, and access frequency may themselves be sensitive.

**RM-SECRETS-VERSION-0005:** Duplicate or equivalent values are not detected through secret-derived hashes by default. Products requiring reuse detection define a dedicated protected verifier and threat model.

**RM-SECRETS-VERSION-0006:** Generated secrets bind entropy source, format/alphabet, length, rejection rules, target constraints, policy generation, and delivery exposure without retaining generated bytes in conformance or benchmark artifacts.
