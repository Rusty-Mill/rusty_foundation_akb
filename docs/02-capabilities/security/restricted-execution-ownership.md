## Ownership duties

The owner maintains manifest semantics, provider resolution, pre-release verification, allowlisted inheritance, attenuation, degradation, evidence/results, readiness, supervision, failure/cancellation, descendant control, reconciliation, diagnostics, dependencies/profiles, source/quality review, conformance, benchmarks, and dossier boundaries. Provider owners maintain separate Windows, Linux, and macOS mechanism/configuration/privilege/signing/container frontiers. Selecting-product owners retain executable trust, workload behavior, requested authority, UX, deployment threat model, and permitted-degradation decisions.

## Bounded trial plan

A later disposable trial may exercise one inert probe child per platform under an exact non-production manifest. It may validate rejection and preparation, create the child without application-controlled execution, apply and verify the native restriction composition, release to an authenticated readiness handshake, probe allowed and denied filesystem/network/IPC/process/descendant actions, then stop, reap, reconcile, and close. Stage-specific injected faults, cancellation, supervisor termination, child misbehavior, and exact explicitly permitted degradations are included.

The trial uses the [foundation trial template](../../05-governance/implementation-trials/trial-template.md), disposable least-privilege identities/containers/packages, generated nonsensitive fixtures, bounded resources/time, isolated native code, and no production credentials, secrets, endpoints, or data. It does not select public Rust APIs, crates/workspaces, a universal sandbox strength, production packaging, supported platform generations, default manifests, degradation policy, performance budgets, or release support.

Stop conditions include any application-controlled execution before verification, unlisted inheritance, authority expansion, silent/late degradation, ambiguous code-execution or ownership state, leaked child/descendant/prepared authority, inability to terminate/reap/reconcile, sensitive diagnostics, unbounded resource use, unsafe host changes, provenance loss, or material contract/environment drift.

**RM-SECURITY-RESTRICTED-OWNER-0001:** Promotion and trial records MUST name accountable people for the unit and every claimed provider/composition/platform/deployment context, exact generations/configuration, reviewer independence, and unresolved limitations.

**RM-SECURITY-RESTRICTED-OWNER-0002:** Trial hypotheses MUST distinguish planning, preparation, creation, restriction application, verification, release, readiness, supervision, termination, reaping, cleanup, cancellation, and indeterminate outcomes.

**RM-SECURITY-RESTRICTED-OWNER-0003:** This bounded plan is evidence only and MUST NOT authorize implementation, native/unsafe code, host security changes, identities/credentials, signing/entitlements, packages, containers, network access, persistent services, production workloads, or release.

**RM-SECURITY-RESTRICTED-OWNER-0004:** Closeout MUST account for every child/descendant, prepared authority, native handle/descriptor, identity/container/package fixture, filesystem/network/IPC artifact, log/trace, and host policy change; remove only verified disposable assets and retain sanitized negative evidence.
