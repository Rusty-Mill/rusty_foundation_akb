# Glossary

- **Capability:** A named unit of behavior an application may require, inspect, and receive from a provider.
- **Service:** A cohesive runtime facility that coordinates one or more capabilities.
- **Interface:** The typed interaction surface exposed to a consumer.
- **Behavioral contract:** Normative guarantees, non-guarantees, failures, timing, safety, performance, and observability for a capability.
- **Backend:** A platform-specific provider that realizes capability contracts using native mechanisms.
- **Resource:** An owned or borrowed entity with an explicit lifecycle and authority boundary.
- **Event:** A typed observation of a state transition or external occurrence.
- **Policy:** A separately configurable rule governing selection, authority, quality, or behavior.
- **Profile:** A named, versioned set of required and optional capabilities for a workload class.
- **Conformance:** Evidence that a provider satisfies a contract for a declared platform and configuration.
- **Degradation:** A declared reduction in quality or guarantees that remains within the contract.
- **Emulation:** A non-native realization of behavior whose semantic and performance differences are explicit.
